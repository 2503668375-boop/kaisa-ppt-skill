# 从方向和大概内容到可汇报成品

## 用户只需给方向

用户期望提出方向、项目与大概内容后，Agent 自主完成结构、资料整理、正文、图表、配图、排版和必要校核。不能把章节填空表、逐页写作和设计决定交回用户。

复用已有上下文和可访问项目文件，先查当前资料；常规选择自行判断。只有无法从资料解决且会改变结论的少数问题才集中询问，例如汇报对象究竟要批准什么、核心财务口径、本次审批事项。问题未回复时继续推进独立部分。不要每个章节、每张图都要求确认。

## 1. 确定本次要解决的决策

按用途确定阅读型或展示型承载。日常经营、定价、投资、产品、推售和专项方案默认是可查阅的公司报告，含主席汇报；只有明确的年度成果展示、发布或演讲才使用展示型大图大字。遵循 [专项汇报密度](company-report-density.md)，不增加已明确事项的问答。

按 report-options.md 明确本次汇报对象（主席或其他具体领导）、是否需要一页纸材料及所用模板。前两项缺失时集中询问，继续不依赖答案的资料工作；不能以受众假设代替明确要求。按已知职责组织关注点。例如“定位研判”着重市场与客户如何推导产品，“推售汇报”着重货盘、价格、客户储备、节点与回款，“方案评审”着重现方案问题、调整依据和实施影响。

按 reporting-logic.md 形成内部工作目标、建议、关键依据与页序。明确完整论证和独立阅读的完成标准。不要在成品中加入“本报告旨在全面赋能”等泛化导语。

## 2. 建资料底稿，解决决定结论的缺口

定向读取当前项目相关文件，记录日期、版本和证据属性。材料可能包含“已批准、草案、建议、预测、历史样本、待核实”，不能混用。

缺少资料时优先自主寻找：项目现有文件、用户已连接的资料源、必要的公开官方资料。涉及会变化的市场、政策、价格和统计必须查当期来源。研究只服务决策缺口，不无限扩展区域背景。

不要为了填模板而假造客户访谈、实际成交、建筑图纸、获批指标、费用、价格或租金。对于当前无法取得且影响判断的事实，在私有底稿记录缺口，优先自主补足；仍无法解决时在聊天中集中说明或追问。成品可用“预计”“计划”“测算情景”等准确业务名称，不能把资料核验或口径认定任务编成汇报章节。若缺口阻断核心结论，在聊天中说明交付限制，不输出虚假的确定结论。

## 3. 自主形成完整的推导

以页序组织“为什么得出这个建议”，不只按资料文件顺序拼接。选用所需路径，不强制套满所有章节：

- 定位：项目条件 → 市场竞争与需求 → 客户约束 → 定位取舍 → 产品与价格/去化关系 → 实施条件。
- 推售：经营任务与可售货盘 → 市场/客户证据 → 推售和价格选择 → 展示/渠道/活动 → 时间与回款安排。
- 产品评审：约束与现方案 → 具体问题 → 调整方案 → 对空间、成本、经营的影响 → 待决事项。
- 经营复盘：目标与实际 → 差距成因 → 可控动作 → 后续安排。
- 活动立项：销售任务与客户问题 → 选用资源的理由 → 活动内容与客户承接 → 投入结构与交付 → 实施安排和真实待决事项。不能只按“目的、流程、布置、预算”罗列执行内容。

篇幅由完整论证和用户要求决定。需要长篇报告就充分展开，不因“少废话”压成十页摘要；短汇报则明确选取决策所需内容，必要附件单独组织。

结论从本次业务任务和已有证据推导，不自行加入安全余量阈值、双重门槛、二次授权或退出安排。真实约束写清金额、日期和影响，资料缺口留在后台处理。

每页都记录其新增信息和独立成页的理由。检查标题、证据和业务含义是否一致；把弱相关的执行细节归并，避免用章节数量制造完整感。总览页只保留导航与关键判断，后文承担依据；总结页只汇合取舍和需要决定的事项，不把所有标题再念一遍。

## 4. 文稿与图文同时设计

先写清主张和依据，再挑适合它的原稿页型；遇到关键图纸或表格，可先确定证据框，再写解释。两者可以迭代，不能先套 20 页框后硬填字。

为每页确定完整的业务回答及证据组合，再选择位置图、比较表、数据图、产品图纸与正文。普通指标集中为紧凑字段，图片大小由实际证明作用决定。必要的财务、价格、经营与产品对照表完整保留；空间提案确需意向图时再生成。不能从“一张大图＋两个大数字”的固定组件反推内容。真实地图与批准图纸保留原始材料。

按 design.md 将新页与越海同类页并排比较信息组织；分析内容不足时补证据、重写解释或合并页面，不能直接进入美化。按 `composition-detail.md` 调整对齐、裁切、比例、图注和段落间距。既学页面结构，也学每个模块为何占这个位置、这张图为何取这个比例。

重排前记录每页必须保留的事实、构成、比较、原因、计算、取舍、动作与必要条件，完成后逐项回查。低密旧稿按同一决策合并相关页，不将原页数或原图框视作限制。用户说文字偏少时，补缺失的论证，不平均拉长每页。主图、图表和正文共同承担信息；长文需要调整栏宽、模块或承接页，不能默认删字或缩字号。

## 5. 成稿必须形成可用文件

用户要求佳兆业汇报 PPT 时，默认面向可编辑 PowerPoint 文件和便于预览的版本；当前会话另有指定目的地时服从。只交提纲、提示词、版式建议或一组图片，不算完成汇报作品。

原生文字、数据图表和表格应可修改，图纸和照片的来源留存私有底稿。交付文件遵循 writing.md 的成品要求，不包含资料来源说明、口径认定、事项核定、校验清单、内部制作备注、占位字、未替换模板页或演练数字。

需要一页纸时，以 PPT 定稿为依据，按 one-page.md 选取最影响受众判断的信息并提炼概括，另交独立的一页材料及便于打印的版本；检查实际只有一页、可读，并与 PPT 一致。明确不需要时不额外生成。

## 6. 汇报前读一遍、看一遍、核一次

- 按管理者阅读顺序通读：主张是否由证据支撑，投入与资源、问题与措施是否对应；是否看得出建议、依据、代价和条件；有没有需要跳回前页才能理解的断点。
- 按专业复核阅读：数值、口径、单位、合计、引用、图纸和文字是否一致。
- 按实际页面阅读：每页无溢出和遮挡，图组有共同边界，长文可读，表格与图注清楚。
- 按成品使用检查：文件可打开、页序正确、文本可编辑、必要业务条件保留、后台来源记录可追溯、保存位置可用。

仅完成制作或接口成功不代表“可以直接汇报”。只有内容、证据、视觉和文件均通过才这样表述。真实审批和关键数据尚未明确时，在聊天中具体指出缺哪项；不在汇报文件中附加笼统免责声明或核定清单。

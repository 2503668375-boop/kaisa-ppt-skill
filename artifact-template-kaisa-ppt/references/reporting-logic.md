# 工作汇报的逻辑与结构

## 从议题由来到会后结果

经营与审议型材料可按以下问题组织。培训、告知与交接按实际用途取舍。

底稿先写一句有出处的现状，再说明它对业务意味着什么。说明既有方案时，沿用原案列明的场次、范围、分工和费用。只有议题确实需要选方案时，才引入有事实基础的对照，说明投入与预期结果。只有相关性时保留判断的限度。

链路的详略随汇报目的变化。决策请示重点在方案取舍与经营影响；经营复盘重点在差距归因与改进；进度协调重点在依赖、责任和日期；外部汇报重点在事实、履约、计划与支持事项。

营销提案先问“拿掉活动名字，项目还面临什么销售问题？”把市场趋势与项目目标、同口径的有效客户数或来访记录放在一起判断。再从客户第一次接触项目，到预约、实际到访、选房，找到想改变的那一步。若到访充足、选房率低，先查产品、价格或接待问题；只有目标客群接触或到访不足时，新增邀约才直接回应症结。多场活动分别说明原案所列的对象、作用和安排。某场的日期或人数未定，只涉及排期或接待规模，不据此推断该场是否举办。合作机会、开放条件及报价能说明如何实施，不能单独支撑立项。详见[调研依据和实例](decision-and-marketing-brief.md)。

汇报预算时，按报价列明各分项用途和合计。仅在用户明确要求测算范围变化时另核单独报价。受邀人数、回执、实到和成交各按原有定义表述。效果测算只用于本次议题确实需要核算的指标。

## 按议题选用的汇报结构

| 类型 | 开篇回答 | 正文支撑 | 收束结果 |
|---|---|---|---|
| 岗位交接或培训 | 本次交付什么、谁需要会做什么 | 现场步骤、示范、岗位接口和常见例外 | 可直接使用的操作或交接信息 |
| 服务改进或技术复盘 | 客户或系统受到什么影响 | 业务量、时间分布、异常原因、候选处理方式 | 本次措施与验证方法 |
| 主席决策 | 结果、核心问题、推荐方案与需决策事项 | 关键事实、方案比较、价值与代价、现金/收益/回款等适用指标、实施条件 | 决策项、推荐选项、资源与关键节点 |
| 经营复盘 | 完成多少、差多少、主要原因 | 目标/实际/同期 → 贡献与差距 → 原因证据 → 动作与预测 | 决议、责任人、完成物、日期 |
| 营销推广 | 当前销售或获客处在哪一步，为何此时值得投入 | 货源、客户行为或具体机会 → 现有做法与拟办活动分别能做什么 → 对应的客群、安排和费用 | 交代预算和实际可核实的来访、复访等结果，按本次目的收束 |
| 投资定位 | 项目机会与核心取舍 | 土地/市场/客户/竞争 → 产品与价格 → 成本资金与回报 → 推荐方案 | 方向选择、测算条件、投资决策 |
| 产品审议 | 现方案哪项影响使用或经营，建议怎么改 | 原图和指标 → 问题及影响 → 调整对照 → 空间/成本/运营结果 | 选定方案、深化要求、接口条件 |
| 外部专项 | 事实、履约、当前困难与具体诉求 | 正式事实 → 已履责任 → 困难及影响 → 计划 → 双方动作 | 支持事项、责任与时间 |

这些顺序用于组织论证，不要求每项各占一页。背景、机构介绍、流程和效果图按本题取舍；有助于读者识别对象、理解作用机制、判断方案或执行工作时保留。

## 正文题名与页序

核心回答要能被读者复述。审议事项写清建议选择什么、受什么条件影响。工作交接写清交什么、从何时开始以及谁接手。左上短标题分别点明各页的事项，连读页首概论应能看出事实、判断与安排之间的关系。

## 主张、证据与业务含义

- 上层结论必须由下层材料支持。价格、数量、时间、客户行为、空间条件和实际结果可以作为证据；“提升品牌、增强体验、形成传播”不能单独作为证据。
- 同层事项采用同一分类依据。客户需求、媒体形式和活动流程不能混成一组并列优势；总额与分项不能混成同口径比较。
- 为本题选有效的比较基准。解释差额时核对统计期、范围、单位和分母，列出主要分项。只有差额数据时只能写差额，不能据此断言原因。
- 建议交代解决什么问题、作用于什么对象、采用什么做法、需要哪些资源、何时完成。
- 方案比较围绕真实决策字段，如货值、回款、成本、总价、速度、空间、交付和权利义务；没有可比方案时不虚构比较。
- 效果预测与实际结果分开，资源数量不得直接折算为成交承诺。
- 数据冲突时说明统计期、对象和口径差异，选择本次采用口径；不得无声平均或随意取较大值。

## 每页完成一个充分回答

普通正文页左上角写具体事项，标题下用一两句概论交代判断或安排。下方用图表、图片或图纸支撑概论。需要连贯解释的理由可以分段写；仅说明一个差额、尺寸或日期时，把依据放在对应数据行、图纸部位或时间节点旁。

页序底稿可按“页码／业务问题与答案／新增依据及其呈现方式”每页一行。把依据与这页相邻的前后内容对照，就能看出为什么要单独成页。表格中的基准、金额和口径能直接支持判断时，用一句话解释差异即可。若连续三页分别只有一个普通数字、一句同义概括和一张氛围图，合并有用的信息，删去无关图片。没有真实对照就收窄结论，不配凑数的图表。详见[阅读型汇报的信息密度](company-report-density.md)。

## 决策、决议与诉求要区分

### 决策请示

列出需要受众决定的事项、推荐选项、关键依据、资源和生效时间。未获批准的方案写“建议”或“测算情景”，不写成已执行。

### 经营会议

列出会议需要确认的责任、完成物、日期和协同。动作与前文问题一一对应，避免“加强、持续、优化”没有完成标准。

### 外部支持

列出请求对方支持的具体事项、项目方已承担和将继续承担的责任、时间安排。诉求与前文事实直接对应，不使用空泛的“恳请大力支持”。

## 附件与主稿分工

主稿保留影响判断的关键证据、比较、投入、条件和责任。附件承载逐套价表、完整测算、长合同条款、逐分钟流程、明细图纸和补充口径。

不得把支撑核心结论的依据全部移到附件，也不得把主稿原样复制到附件。附件页同样需要标题、单位、日期和可读版面。

## 页序终审

1. 连读各页概论，能否从起因讲到选择与落实？前一页的哪个问题引出本页，本页的答案凭什么支持下一步？若只能复述章节名，重写判断或调整页序。
2. 每个关键结论能否找到对应事实、比较、图纸或计算？
3. 同一主张是否被换词重复，缺少新增证据？
4. 删除某页是否损失独立信息？无损失则合并或删除。
5. 是否把一项完整论证拆成多页提词卡？需要时重新编组。
6. 主席能否找到结果和决策项，管理层能否找到责任和日期，外部对象能否找到履约与诉求？
7. 结尾是否产生本次会议真正需要的结果？

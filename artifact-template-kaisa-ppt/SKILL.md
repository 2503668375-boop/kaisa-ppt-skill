# 佳兆业汇报 PPT

## 按交付物选择流程

单独要一页纸时，直接使用[通用 Word 母版](assets/one-page-report.docx)和[一页纸写作与排版](references/one-page.md)。个人或团队均可署名，栏目、数量和顺序随议题确定。以下制作流程用于整份 PPT 或实质性改稿。

## 交付目标

接收一个议题、项目名或零散材料后，交付一份能直接用于会议的完整材料。成品应让目标读者迅速看清结果、依据、取舍和下一步，并能承受会上对数据、价格、货盘、费用、节点和责任的追问。

工作优先级：当前用户要求与已确认事实 > 本次汇报任务简报 > 汇报对象与会议目的 > 越海同类页的信息组织 > 模板与工具默认样式。

历史样本用于学习品牌、密度和图文关系。样本中的项目名、数据、政策、产品方向、价格和结论不得进入新任务，除非本次资料再次确认。

## 公司模板继承（硬约束）

用户指定公司原稿、提供参考 PPT，或任务命中本技能内置模板时，必须以对应原稿副本为制作起点。保留原稿的母版、页面尺寸、佳兆业标识、页眉线、封面、字体体系、颜色、标题位置、正文网格和可编辑对象。不得从空白 PPT 重新画一套“类似风格”，不得让通用工具的画布、卡片、大数字和版式规则覆盖公司原稿。

公司标准分析页按四层组织。对于时序图、整幅图纸和明细表，按同类原稿安排阅读顺序，判断和依据可贴近相应节点、图注或字段，避免复述。

1. **左上角标题**：具体议题或判断，沿用原稿位置与字号。
2. **页首一句话概括**：用完整业务句概括本页结论，使用本稿唯一主强调色。
3. **分段依据**：用两至三条有具名对象的事实、比较或原因支撑概括；每条包含实际信息。
4. **主体证据与排版**：下部放完整表格、图纸、地图、竞品参数或左右对应措施，必要时以页底结论收束。

普通分析页不得用大数字、深色卡片、半页氛围图和少量正文替代这四层。原稿没有视觉锚点配额，信息密度由完整证据和可读图文关系决定。

## 启动：先形成汇报任务简报

制作整份报告或实质性改稿前，读取 [从议题到完整汇报](references/brief-to-report.md)，在私有底稿写清七项：

1. **议题**：本次只回答哪一个业务问题。
2. **由来**：什么目标偏差、节点、外部变化、上次决定或管理要求触发了这次汇报；为什么现在要讲。
3. **目的**：用于知情、复盘、方案审议、决策请示、资源协调或外部支持。
4. **对象**：主席、内部管理层、具体职能负责人，或政府、金融机构、合作方等外部对象；混合受众确定主读者。
5. **内容**：必须保留的事实、比较、方案、费用、节点、责任与资料缺口。
6. **输出**：PPT、决策摘要、一页纸、讲稿或附件；确定阅读型或投影型、页数或时长、数据截止日。
7. **会后结果**：希望受众批准什么、选择什么、协调什么、支持什么，或确认哪些责任与日期。

能从议题、上下文和项目资料判断的内容直接采用。仅向用户询问会改变核心结论或交付结果的缺失项，一轮问完；不得把逐页大纲、常规排版和文案任务交回用户。

## 路由：按对象和目的组织材料

读取 [模板、汇报对象与一页纸](references/report-options.md) 和 [汇报逻辑与结构](references/reporting-logic.md)。同一项目共用事实与计算口径，按主读者改变页序、详略和措辞。

| 主读者 | 开篇先回答 | 主线 | 收束 |
|---|---|---|---|
| 主席 | 结果怎样、关键问题是什么、建议选什么 | 结果与差距 → 核心依据 → 方案取舍 → 经营影响 → 决策事项 | 需拍板事项、方向选择、重大资源与节点 |
| 内部经营管理层 | 目标完成怎样、差距为何产生、怎么追回 | 目标与实际 → 偏差归因 → 动作与资源 → 责任与日期 → 预测 | 会议决议、责任人、完成物、时点 |
| 营销或专业条线 | 专业问题在哪里、方案如何落地 | 货盘/客户/产品等证据 → 专业判断 → 执行方案 → 协同接口 | 任务清单、专业交付、配合事项 |
| 政府、金融机构、合作方 | 当前事实是什么、已履行什么、需要什么支持 | 项目事实 → 履约与进展 → 困难及影响 → 处理计划 → 具体诉求 | 请求支持事项、双方责任、时间节点 |

主席版保留支持决策的关键证据，避免把结果先行误做成只有口号的短稿。内部版不得只有任务表而缺少经营判断。外部版只使用可对外披露的信息，删除内部报价底线、客户隐私、未经确认的归因和内部争议。

## 成稿：先完成论证，再进入排版

### 1. 建事实台账

读取当前任务资料，记录指标、数值、单位、统计期、地域、对象、口径、来源和证据属性。区分实际、计划、目标、预测、测算情景和专业判断。

认购、网签、备案价、成交价、实收、回款、放贷、工抵房分别定义；挂牌价不得替代成交价，全市数据不得替代板块数据，规划不得写成已兑现。来源冲突时保留差异并说明本次采用口径。

缺少关键资料时先自主查找。仍无法取得且影响结论的，降低结论强度或明确测算条件，不补造客户原话、费用、价格、阈值、转化率、批准状态和经营结果。

### 2. 写出一句核心回答

用一句完整业务语言回答本次议题，包含明确对象、判断或建议、主要经营影响。随后列出支撑这一回答的关键依据；数量按实际论证决定，不硬凑。

### 3. 先排标题链，再写逐页内容

标题链连读应能复述：为什么现在汇报 → 当前结果或问题 → 为什么 → 建议怎么做 → 代价与影响 → 需要受众做什么。

每页在私有页表记录：业务问题、页面结论、新增证据、项目影响、所需动作、图文关系、删除或合并测试。没有新增信息的页面删除；一项完整论证被人为拆成多页时重新合并。

### 4. 按中文业务表达成稿

读取 [文字表达](references/writing.md)。标题给判断，正文补证据、原因、比较、方案或条件，图注说明图中对象与必要口径。每一层增加新信息。

使用项目、营销、投资、产品和财务人员能直接进入会议纪要与任务书的语言。删除元话语、空泛商业词、机械三段式、同义重复、伪深刻收尾和无主语动作。专业判断应有依据，执行动作应有对象、责任、完成物和日期。

### 5. 按信息任务设计版面

读取 [视觉参数与中文排版](references/design.md)、[专项汇报信息密度](references/company-report-density.md) 和 [逐页图文细节](references/composition-detail.md) 的适用部分，打开同类参考大图，逐页核对标题、概括、分段依据和主体证据的位置，不只看封面或配色。

保留三套原生参考：橙色越海版 `assets/reference.pptx`、原汇报橙黄版 `assets/reference-yellow-report.pptx`、红色封面版 `assets/reference-red-cover.pptx`。未指定时使用橙色越海版。颜色与职位不绑定，原稿保持不变，在工作副本中制作。

按业务问题选择原稿页型：市场/竞品与决策摘要参考越海 P4；完整配比、经营结果与货值表参考 P7/P10；事实与措施对应参考 P12；双栏比较参考 P9；两项安排与执行参考 P11；决策事项参考 P5。新页只替换业务内容，不将原稿改成通用大数字卡片页。

### 6. 生成真实可用文件

先复制所选原稿，再在副本中保留适用页、替换业务内容和补充原生对象；只有用户明确要求全新非公司模板时才从空白文件开始。选择能保留模板资产与原生对象的一套制作流程，不叠加多套流程，不经过会丢失媒体、母版或字体的重导出通道。

默认交付可编辑 PPTX 和便于预览的版本；用户指定其他格式时服从。文字、表格、数据图表保持可编辑，原始图纸与照片保留清晰图像。保存后核对文件体积、页数、媒体数量和实际渲染，防止模板资产在保存过程中丢失。

仅改文字时保留现有版面。主席或最终决策者汇报默认同时交付独立一页纸，用户指定只做 PPT 时以其要求为准。其他场景按本次交付要求执行。配套一页纸与 PPT 共用数据、建议、时间及待决事项，章节依题组织；只有确有审议事项才写请示。见[一页纸写作与排版](references/one-page.md)。多泳道营销时间轴共用月份网格，节点按真实月份对位。

## 成品验收

执行 [成品验收](references/review.md)，至少通过五层检查：

1. **任务**：议题由来、目的、受众和期望会后结果一致。
2. **逻辑**：核心回答有证据，标题链完整，结尾形成对应决策、决议或支持事项。
3. **文案**：每句有明确对象和实际信息，无 AI 套话、旧项目残留、伪造事实和重复结论。
4. **版面**：逐页渲染检查中文换行、字号、对齐、溢出、遮挡、图表标签、图纸清晰度和页序。
5. **文件**：可打开、可编辑、页数正确、数据一致、保存位置可用；说明实际验证范围和未解决限制。

不得将导出成功、模板相似或自动检查通过表述为“可以直接汇报”。业务分析、中文表达和实际页面均合格后，才可这样交付。

## 稳定偏好与使用边界

- 越海样本是信息密度与图文组织的主标杆，橙色和标识只是其中一部分。
- 每份报告只设一种主强调色。橙色越海版的页首概括、重点文字和结论带统一使用越海橙，正文黑色，深蓝少量辅助；红色封面版才使用红色强调，单稿不混用橙红。
- 禁用“不是……而是……”式翻转、空泛的“赋能/抓手/闭环/打造”和没有业务对象的“高端/品质/标杆”。
- 不用“本页、后续页面、四项判断”等文档自述填补正文，不把工作标签渲染到汇报页面。
- 方案写出具体取舍、投入、影响和动作，不自行添加安全垫、二次审批、退出机制或未经证实的承诺。
- 用户提供的经营与客户资料留在私人工作环境；公开演示使用明确标注的模拟数据。
- 本地原稿、客户与经营材料不对外分发。

# 从议题到完整汇报

## 最小输入与自主完成范围

用户可以给一个议题、项目名、一次会议场景或一批零散材料。Agent 自主完成资料整理、论证、正文、图表、配图、排版、文件生成和校核，不要求用户逐页供稿。

只有以下缺口会影响核心结论或成品用途时才集中询问：汇报主读者无法判断、需要批准或协调的事项不明、关键经营口径冲突、核心数据缺失、保密范围不明。其他选择按本技能默认规则推进。

## 第一步：写汇报任务简报

在私有底稿完成下表，不将字段名或填写过程放进汇报文件。

| 字段 | 要写清的内容 | 检查问题 |
|---|---|---|
| 议题 | 一个具体业务问题 | 这次只讲透什么 |
| 由来 | 触发事件、上次决定、当前偏差、管理要求或外部变化 | 为什么现在必须讲 |
| 目的 | 知情、复盘、审议、决策、协调或外部支持 | 会议要完成什么 |
| 主读者 | 职务、分管事项、已知关切；混合受众确定优先级 | 谁最需要听懂并行动 |
| 核心回答 | 一句有对象、有判断、有经营影响的话 | 听完记住什么 |
| 所需行动 | 批准、选择、资源、协同、确认责任或外部支持 | 会后发生什么 |
| 非目标 | 本次不展开的历史背景、旁支议题和无关专业细节 | 哪些内容应删除 |
| 交付 | PPT、摘要、一页纸、讲稿、附件及保存位置 | 以什么形式使用 |
| 使用条件 | 阅读或投影、会议时长、页数、数据截止日、保密级别 | 如何控制密度和披露 |

### 议题由来的常见证据

- **目标偏差**：签约、回款、供货、成本或工程节点偏离预算、年度目标、上月计划。
- **经营节点**：推售、定价、开盘、交付、投资、合作、合同或付款节点临近。
- **外部变化**：政策、市场、竞品、融资、合作条件或政府要求发生变化。
- **上次决定**：上次会议明确的事项到期，需要报告结果或调整方案。
- **管理要求**：主席、经营会、职能部门或外部机构提出明确问题。
- **例行业务**：周报、月会、季度经营会需要更新结果、偏差和安排。

由来要落到具体事件、数字、日期或文件。写不出由来的“重要性、战略意义、行业趋势”不得占据开篇。

## 第二步：判断本次要产生哪种结果

| 汇报目的 | 开篇重点 | 主体内容 | 最后一页必须形成 |
|---|---|---|---|
| 决策请示 | 推荐方案与经营影响 | 关键依据、方案比较、投入、风险与实施条件 | 明确决策项、推荐选项、需批准资源 |
| 经营复盘 | 目标、实际与差距 | 构成、归因、可控因素、后续预测与动作 | 决议、责任、完成物、日期 |
| 方案审议 | 现方案问题与调整建议 | 图纸或业务证据、调整对照、成本与经营影响 | 选定方案、深化要求、接口条件 |
| 进度协调 | 当前状态与关键堵点 | 节点、依赖、影响、责任接口与解决安排 | 协同事项、责任方、完成时间 |
| 外部支持 | 事实、履约与具体诉求 | 项目进展、已履责任、困难、计划和影响 | 请求事项、双方动作、时间节点 |
| 知情通报 | 最重要结果与变化 | 必要依据、影响、下一步 | 需知悉事项；无决策时不硬造请示 |

纯进度或知情材料可以不设备选方案。涉及真实选择时，给出明确推荐及理由，不把多个方向平铺给领导挑选。

## 第三步：建立事实台账与缺口清单

每条关键数据记录：指标、数值、单位、统计期、地域、对象、来源、发布日期、口径、证据属性和允许推断范围。

证据属性统一为：

- **实际**：已经发生并可追溯的结果。
- **目标/计划**：公司或项目确定要完成的任务，注明版本与日期。
- **预测**：基于当前信息对后续结果的判断，写明关键假设。
- **测算情景**：按指定输入计算的结果，保留公式和输入，不写成实际成交或批准方案。
- **专业判断**：由事实和推导支持的建议，注明失效条件或需要继续观察的信号。
- **资料缺口**：缺什么、影响哪项结论、能否通过其他资料补足。

优先使用当前项目原始资料。市场、政策、融资、价格和统计信息具有时效性时查当期权威来源。引用公开信息保留必要出处；内部工作文件路径、单元格地址和脚本结果留在后台。

无法核实的数字不进入主稿。缺少非关键细节时缩小句子范围；缺少核心数据时改为条件测算或说明无法形成定案，不用通用建议填满页面。

## 第四步：形成标题链和页序

标题链按本次目的组织，不套用固定目录。常用推导路径如下：

- **主席决策**：结果与核心问题 → 关键事实 → 方案取舍 → 经营影响 → 推荐方案 → 决策与节点。
- **经营复盘**：经营结果 → 目标差距 → 产品/渠道/费用/节点构成 → 原因 → 改进动作 → 后续预测与责任。
- **推售定价**：销售与回款任务 → 可售货盘 → 市场及客户证据 → 价格与推售取舍 → 营销承接 → 节点与回款。
- **产品审议**：约束与现方案 → 具体问题 → 调整方案 → 空间/成本/经营影响 → 审议事项。
- **营销立项**：销售任务与客户问题 → 核心动作 → 渠道/活动/案场协同 → 费用与资源 → 转化安排 → 责任与节点。
- **外部专项**：项目事实与责任 → 已完成工作 → 当前困难及影响 → 后续计划 → 请求支持事项。

篇幅由决策所需证据和会议时长决定。主席简报的主线通常集中在前几页，附件保留测算与明细；内部经营会可增加责任表和专项页；外部汇报删除与请求无关的内部经营细节。

## 第五步：建立逐页内容合同

每页在私有底稿记录：

| 字段 | 要求 |
|---|---|
| 页码与业务问题 | 本页回答什么，避免只写章节名 |
| 判断句标题 | 标题能表达本页结论或明确对象 |
| 新增证据 | 数据、比较、图纸、客户行为、正式文件或计算 |
| 解释与影响 | 证据为何支持判断，对销售、回款、成本、产品或节点有何影响 |
| 动作与条件 | 谁做什么、交付什么、何时完成、需要何种资源 |
| 图文关系 | 哪种证据应成为视觉重心，正文放在哪里 |
| 来源与口径 | 数据截止日、单位、必要出处与计划/实际属性 |
| 删除测试 | 删除本页会损失什么；无损失则合并或删除 |

标题、导语、正文和页底不得重复同一句话。正文不能只留关键词，必要长句、完整表格和技术条件应保留。

## 第六步：文稿与版面同步制作

先确定本页证据与阅读顺序，再选择同类样本页型。关键图纸或表格可以先定证据框，正文围绕它解释；不得先套固定页数再填字。

- 区位和地块用真实地图、红线、航拍与标注。
- 经营与市场用同口径数据图、构成表和原因解释。
- 客户用行为、预算、家庭和使用约束，少用身份标签。
- 产品用平面、剖面、尺寸、楼层和空间对照。
- 营销用货盘、客户漏斗、渠道、节点、费用和案场承接相互对应。
- 执行页用责任、完成物、日期和依赖关系，避免只有“持续推进”。

空间提案确需画面且缺少素材时可生成设计意向图，标注“设计意向（AI生成）”。不得生成地图、成交证据、批准图纸或项目实景冒充事实。

## 第七步：交付与汇报前检查

默认交付可编辑 PPTX 和预览版本。需要时附决策摘要、一页纸、讲稿或测算附件，各文件共用同一事实源。

按目标读者通读：能否快速看到结果，能否找到依据，能否判断投入与代价，能否形成会议决定。按专业口径复核：数值、单位、合计、时间、图纸和文字一致。按实际页面检查：中文换行、字号、图表标签、图片比例、溢出和遮挡合格。

真实审批、关键数据或素材仍未确定时，在交付聊天中具体说明。汇报文件不附 AI 自评、生成过程和笼统免责声明。

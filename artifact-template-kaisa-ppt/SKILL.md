# 佳兆业 PPT

## 目标与优先级

用户认可的是前海越海样本的**专业表达、内容详实、图文组织与阅读舒适度**，不能只复制橙色和标识。交付应让管理者看清项目判断、依据、取舍与执行条件，同时让设计、营销、投资人员能查到必要细节。

优先级：当前用户要求 > 当前任务已批准的内容与事实 > 相应载体的主样本（PPT 用越海原稿，一页纸用通用 Word 母版） > 辅助报告的适用做法。历史样本只供表达与版式学习，其中产品配比、价格、酒店办公方向、市场数据、政策及预测均不构成新任务的事实或授权。

本技能覆盖从简要方向到可直接汇报成品的组织、写作、图文设计与验收。选择一个实际制作流程完成工作，不叠加多套制作流程。仅改文字时不启动演示文稿制作。

## 默认采用公司专项汇报密度

日常经营、市场研判、投资、产品、定价和推售方案默认采用阅读型密度，主席汇报同样如此。内容页需将事实与构成、比较或计算、原因及影响、建议和必要条件组织成完整回答。普通分析页不采用“一张大图＋几个大字＋少量说明”的展示型主结构。

明确的年度成果展示、形象发布或演讲可用较低密度；年度经营复盘和预算审议仍需充分分析。用途已知时直接执行，不增加确认环节。制作内容页或纠正低密度报告时，读取[公司专项汇报的信息密度](references/company-report-density.md)，按越海同类页的证据组合编排，再分配图、表、文字与留白。

## 默认承担的工作

用户只需给方向、项目与大概内容。由 Agent 自主组织论证、查找必要资料、撰写完整正文、选择项目素材、按需生成设计意向效果图、制作图表、安排页序与图文、校核并交付可编辑成品。不要要求用户提供逐页文案或替 Agent 作常规设计决定。遇到会改变结论的关键事实缺口才集中询问，其他工作继续完成。

选择模板、实质性改稿或整稿重排时，读取[模板识别、整稿改写与内容保留](references/revision-lessons.md)。以当前指定原稿确定模板身份，以越海同类页检验信息密度与图文关系。低密旧稿需要重新聚合证据和调整页序，不能只保留原版再补两句正文。

“可以直接汇报”以内容和证据完整、文字专业、实际页面可读、文件可用为标准，不能仅凭模板相似或导出成功宣称达成。默认按**可独立阅读的经营汇报**组织，正文充分展开。主席需要快速掌握结论，也需要能当场查阅的依据、取舍与投入说明；不将“主席版”处理成每页两三句的演讲提词稿。

## 每次任务明确的事项

单独制作一页纸时直接进入[一页纸写作与排版](references/one-page.md)。按实际读者和用途成稿，个人、团队或单位均可使用。下列汇报对象和 PPT 模板选项用于制作公司演示文稿。

- **汇报对象**：明确是主席，还是主席以外的领导；后者还需明确职务或分管事项。主席版突出关键判断、经营影响、方案取舍及真实需要决策的事项；其他领导版围绕其职责展开专业依据、执行安排与协同事项。不得只换称呼，也不得把主席版简单等同于删减页数。
- **一页纸材料**：从[通用 Word 母版](assets/one-page-report.docx)起稿，继承页首、字体、字号、字重、行距、页边距与编号样式。每次按议题决定正文写什么、分几节、怎样排序，简单事项可以只写一段。见[一页纸写作与排版](references/one-page.md)。
- **模板**：技能内提供“橙色越海版”“原汇报橙黄版（雲玺样本）”和“红色封面版”，按当前指定选用；未指定时沿用橙色越海版并告知。颜色选择与汇报对象独立，不自行绑定“主席只能用红色”。

制作公司 PPT 时，汇报对象或配套一页纸要求缺失的，合并简短询问：“这次汇报给主席，还是哪位领导（职务/分管事项）？是否需要另做一页纸材料？”等待期间可继续资料整理、事实核对和通用图表，不擅自定稿依赖这些答案的内容。具体内容取舍、模板路径及一页纸组织见 [模板、汇报对象与一页纸](references/report-options.md)。

## 公司汇报的成品要求

公司汇报直接讲经营结果、原因、判断、方案和行动。资料来源追溯、口径认定、表格校验、事项核定及制作验收由 Agent 在后台完成，默认不进入汇报文件，包括正文、页脚、附录、隐藏页和演讲者备注。具体写法和例外见 [文字表达：后台工作与汇报内容](references/writing.md#后台工作与汇报内容)。不得只改名后把这些制作任务包装成经营风险或协同事项。

## 开始时读取

1. 只有方向或零散材料时，先读 [从方向到完整汇报](references/brief-to-report.md)，自主补全工作计划与证据。再读 `artifact-template.json`，解析相对路径。`assets/reference.pptx` 是完整越海原稿；红色封面版另保留 `assets/reference-red-cover.pptx`。原汇报橙黄版为 `assets/reference-yellow-report.pptx`。颜色名称不能替代文件身份；有当前截图或明确原稿时优先匹配。按 [模板选择](references/report-options.md) 读取适用原稿，原稿保持不变，在工作副本中制作。
2. **凡涉及整份报告或实质性改稿，读取 [汇报逻辑与结构](references/reporting-logic.md)**，形成决策问题、主张与证据的对应关系；正文撰写读取 [文字表达](references/writing.md)。需要一页纸时读取 [一页纸的取舍与提炼](references/one-page.md)。文字质量与视觉质量同等重要。
3. 设计页面时读 [视觉参数与页面库](references/design.md) 和 [逐页图文细节](references/composition-detail.md) 中适用部分，打开匹配页型的本地参考图片。主要样本见 `references/visuals/yuehai-01.jpg` 和 `yuehai-02.jpg`；完整大图见 `references/visuals/full/p-01.png` 至 `p-20.png`。不要只看封面或缩略图。
4. 需要更多经营、投资、产品或营销结构时，按 [样本索引](references/sources.md) 读取对应资料，不重新扫描全部硬盘。

## 工作方式

### 明确这一份报告要解决什么

复用对话中已有的受众、用途、页数、品牌及交付位置。只有缺失信息影响结果时才问。佳兆业公司汇报沿用标识；用户仅要求学习风格、报告属于其他主体时，使用其实际品牌，不能误署佳兆业。

制作前检查所需输入、源图、字体和保存位置。用户当前提供的文件优先。默认形成适合会后阅读的专业报告，内容较密但可辨认；明确用于远距离投影时放大字号并重新分页，不靠删除关键依据解决。

### 文字与页面同步组织

按 reporting-logic.md 在私有底稿记录：本页回答的业务问题、具体判断、支撑证据、业务含义或方案取舍、对下一页的作用。不能只列章节名就开始套版。每页集中回答一个业务问题，同时容纳回答它所需的多项事实、比较和解释。

排版前用“为什么、凭什么、与什么相比、对业务有什么影响、具体怎么做”检查必要论证。资料已具备时自主计算和推导；关键事实缺失时定向补充，不用通用建议替代分析，不靠多拆页或放大图片撑篇幅。

- 一条正文至少承担一种功能：提供事实、解释原因、比较方案、说明动作、界定条件。只表达态度、气势或重复结论的句子应删改。
- 每一页左上角必须标明本页主题，正文与图片从主题区下方开始；封面、目录、章节页和结束页同样适用。主题可用“市场研判｜竞争格局”等具体短语，不能只放页码或标识。标题定位议题或概括判断；导语补足核心逻辑；正文展开依据与取舍；图注解释图中对象、范围、单位和必要时间；来源记录留在私有底稿。各层增加新信息。
- 同一判断在首次完整论证后，后页只在需要承接时简短引用，并补上新的证据、空间安排、产品参数或执行措施。不能用同义词把它铺满全稿。
- 保留影响结论的数据、比较口径、机制、时间节点与条件。完整报告不能退化成摘要、口号或关键词列表。
- 逐页检查新增信息：若相邻页只有主题名和说法不同，合并并补充证据；若缺少事实、比较或方案细节，回到资料补足。不得把相同场景图反复配泛化说明视作新增论证。
- 不为凑页数添加“背景重要性”“战略意义”“总结展望”等空页，也不把报告生成过程、免责声明模板和质量自评塞进正文。
- 文案直接陈述项目价值、经营结果和实施方案。禁用“边界”“先……后……”“先……再……”及同类防御性、机械顺序句式；不自行增设安全垫、投决门槛、暂停推进、二次批准或退出逻辑。具体改写见 writing.md。

### 按内容选择载体

先用主样本中相近页面的结构，再按材料调整。定位报告通常形成市场/地块/客户到产品与行动的推导，但不强制每份报告包含全部章节。

- 区位与地块问题用真实地图、航拍、规划图配标注。
- 竞争与经营问题优先采用项目图像、原生数据图表和必要解释。表格只用于财务测算、指标清单或确需逐项查阅的比较，不作为通篇默认载体。
- 客户定位用需求、支付/使用约束与产品承接关系，少用空泛身份标签。
- 建筑产品问题用平面、剖面、楼层分布、案例照片及设计意向效果图。当空间提案确实需要画面解释且缺少适用图片时，生成与项目相符的建筑、景观、归家、室内或商业场景；不为填满页面或增加图片数量而配图。用简短图注“设计意向（AI生成）”标识。
- 完整分析是内容页的主干，图纸、照片、数据图、比较表和正文按证明作用安排。普通指标用紧凑指标行或表格；带标注的图纸可以作为主体，未参与论证的普通大图不能挤掉货盘构成、价格理由和执行分析。不以图片多、表格少或大数字醒目作为美化目标。
- 橙色越海版采用橙色品牌主线；红色封面版采用红色封面与克制的红色内页强调。各版根据本次模板与内容安排主体阅读区；文字以黑色为主，关键结论、价差与重要数字用红色，深蓝仅少量使用。图片与图表可保留必要配色，不把系列色自动用于文字。避免连续使用深蓝表头、深蓝标签和整页横条，具体色值与组件选择见 design.md。

参考原稿保留不代表每次交付都复制原项目图片和内容。其他项目须替换旧项目名称、版本、数字、图像、备注、页脚及演讲者备注中的历史信息。

### 制作与交付

选择当前环境可用且符合用户要求的一套演示工具。需要原生 PPTX 或指定使用 PPT Master 时，按该主流程加载必要用法；使用 Presentations 时走其参考/模板流程。本技能规定的样本、文字密度与图文关系优先于工具的通用大字号、极简卡片等默认风格。

能继承的母版、页眉、封面和原生对象在副本上继承。可编辑文本、表格和数据图表保持可编辑；原始图纸作为清晰图像保留。真实地图、测绘与规划图、已批准图纸及成交数据保持可追溯；生成效果图用于表达设计提案，不替代这些事实材料。生图使用当前可用的图像生成工具，按实际调用读取其用法，无须为每张意向图追加确认。

完成后执行 [文字与页面验收](references/review.md)：分别检验业务论证、信息承载与视觉、文件可用性。业务分析不足或页面寡淡，即使无溢出、可打开也不能通过；由 Agent 连续修复，无须新增用户确认。逐页检查实际图文对齐、比例、裁切、段落、图注和页序，渲染并修复。已做试验的范围见 [验证记录](references/validation.md)，不得将局部试做扩大为所有页型已测试。不要把安装成功、导出成功或自动检查通过当作完整验收。在聊天交付说明中简要说明成品、已验证范围及影响使用的未解决问题；不把这段说明写入汇报文件。

方法依据与本次失败复盘见 [调研与佳士得案例校准](references/research-and-retrospective.md)。用于维护或检查再次出现的“页多而信息薄、一页纸只缩写”问题，不作为其他项目的事实来源。

## 已确立的用户偏好

- 越海的信息密度与版式是主标杆。公司专项汇报不采用年度展示式的大图和几个大字；其他样本用于补充，不能将展示型承载量当默认。
- 专业、具体、有判断、有依据；“文字少”应补原因、比较、取舍和动作，不能只加字或扩大标题。正文充分展开必要分析，以越海同类页的信息组织为参照。每页仅大图加少量泛化文字不合格，增加字数也不能代替补充事实和论证。
- 字体颜色克制：黑色为主、红色强调、少量深蓝；避免橙字、青灰字和金色字分散注意。封面和深色底上的必要白色反字保留，不混同于一般正文。
- 图文详实与排版美观同时成立。真实图像与设计意向效果图配合使用，表格集中在确有必要的页面。
- 提供橙色越海版、原汇报橙黄版和红色封面版；按本次指定原稿选择，保留品牌识别元素。图文、辅助色及组件按内容安排，避免单一浅底和同一种构图铺满全稿。
- 文案不使用“边界”和“先……后……”式逻辑，不加入 Agent 自造的防御性推断。
- 避免“不是……而是……”等故作翻转；文案不要反复出现泛化的“赋能、打造、提升、闭环”。这些词只有对象、机制和结果明确时才保留。
- 不默认套黑金豪宅风、科技渐变、全屏口号或互联网仪表盘风。
- 本地原稿、客户与经营材料留在私人工作环境。创建公开演示时使用虚构材料。

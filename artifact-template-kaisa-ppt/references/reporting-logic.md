# 工作汇报的逻辑与结构

## 从议题由来到会后结果

经营与审议型材料可围绕以下问题组织；培训、告知与交接材料按实际用途取舍。

**为什么现在汇报 → 当前结果或问题是什么 → 为什么会发生 → 建议怎么处理 → 对经营有什么影响 → 需要谁做什么。**

链路的详略随汇报目的变化。决策请示重点在方案取舍与经营影响；经营复盘重点在差距归因与改进；进度协调重点在依赖、责任和日期；外部汇报重点在事实、履约、计划与支持事项。

在私有底稿写清核心回答、关键依据和所需行动。简要通知可直接按读者所需的信息成稿。

## 按议题选用的汇报结构

| 类型 | 开篇回答 | 正文支撑 | 收束结果 |
|---|---|---|---|
| 岗位交接或培训 | 本次交付什么、谁需要会做什么 | 现场步骤、示范、岗位接口和常见例外 | 可直接使用的操作或交接信息 |
| 服务改进或技术复盘 | 客户或系统受到什么影响 | 业务量、时间分布、异常原因、候选处理方式 | 本次措施与验证方法 |
| 主席决策 | 结果、核心问题、推荐方案与需决策事项 | 关键事实、方案比较、价值与代价、现金/收益/回款等适用指标、实施条件 | 决策项、推荐选项、资源与关键节点 |
| 经营复盘 | 完成多少、差多少、主要原因 | 目标/实际/同期 → 贡献与差距 → 原因证据 → 动作与预测 | 决议、责任人、完成物、日期 |
| 营销立项 | 销售任务、客户问题、核心动作与投入 | 货盘与客户 → 动作设计 → 渠道/活动/案场承接 → 费用 → 转化与节点 | 选定方案、预算或资源、任务分工 |
| 投资定位 | 项目机会与核心取舍 | 土地/市场/客户/竞争 → 产品与价格 → 成本资金与回报 → 推荐方案 | 方向选择、测算条件、投资决策 |
| 产品审议 | 现方案哪项影响使用或经营，建议怎么改 | 原图和指标 → 问题及影响 → 调整对照 → 空间/成本/运营结果 | 选定方案、深化要求、接口条件 |
| 外部专项 | 事实、履约、当前困难与具体诉求 | 正式事实 → 已履责任 → 困难及影响 → 计划 → 双方动作 | 支持事项、责任与时间 |

这些顺序用于组织论证，不要求每项各占一页。背景、机构介绍、流程和效果图只有承担证明任务时才保留。

## 核心回答与标题链

核心回答是一句可供会议讨论的业务判断，包含明确对象、建议或结论及主要经营影响。例如内部底稿可写成：“建议将 11 月推售资源集中于某类产品，以改善某项销售或回款任务；需要会议确认货量、价格和节点。”其中具体数字与事实必须来自本次资料。

标题链连读应能复述全案。标题可采用以下业务句型：

- 结果：`本月签约完成 X，差额主要来自 Y`。
- 归因：`A 类产品到访充足，价格与付款条件影响成交`。
- 取舍：`高区大户型控制供应，资源集中于主力总价段`。
- 方案：`调整某层平面，将主要景观面配置给客餐厅`。
- 行动：`11 月完成某批货推售，营销、案场与财务按三节点承接`。
- 请示：`建议确认方案 B，并批准对应费用与供货安排`。

上述 X、Y 仅表示字段位置，成品必须替换为真实内容；没有数据时改写句子，不留占位符。

## 主张、证据与业务含义

- 上层结论必须由下层材料支持。价格、数量、时间、客户行为、空间条件和实际结果可以作为证据；“提升品牌、增强体验、形成传播”不能单独作为证据。
- 同层事项采用同一分类依据。客户需求、媒体形式和活动流程不能混成一组并列优势；总额与分项不能混成同口径比较。
- 指标交代与谁比、差多少、由什么构成、为什么、对后续有什么影响。
- 建议交代解决什么问题、作用于什么对象、采用什么做法、需要哪些资源、何时完成。
- 方案比较围绕真实决策字段，如货值、回款、成本、总价、速度、空间、交付和权利义务；没有可比方案时不虚构比较。
- 效果预测与实际结果分开，资源数量不得直接折算为成交承诺。
- 数据冲突时说明统计期、对象和口径差异，选择本次采用口径；不得无声平均或随意取较大值。

## 每页完成一个充分回答

一个业务问题可以容纳多项证据。普通分析页应让读者在同页看到结论、凭什么以及对项目的影响，避免翻多页拼接一项简单论证。

页面阅读顺序通常为：判断句标题 → 主证据或图纸 → 必要解释与比较 → 项目影响或动作。标题已说清的，不再用导语和页底重复。

私有页表至少回答：

| 业务问题 | 页面结论 | 新增证据 | 项目影响 | 动作/条件 | 图文关系 | 独立成页理由 |
|---|---|---|---|---|---|---|

正文应写成可读业务语言，不能只填关键词。图纸页的主要信息可由中国图、标注和尺寸承载，不强制增加字数。

## 决策、决议与诉求要区分

### 决策请示

列出需要受众决定的事项、推荐选项、关键依据、资源和生效时间。未获批准的方案写“建议”或“测算情景”，不写成已执行。

### 经营会议

列出会议需要确认的责任、完成物、日期和协同。动作与前文问题一一对应，避免“加强、持续、优化”没有完成标准。

### 外部支持

列出请求对方支持的具体事项、项目方已承担和将继续承担的责任、时间安排。诉求与前文事实直接对应，不使用空泛的“恳请大力支持”。

## 附件与主稿分工

主稿保留影响判断的关键证据、比较、投入、条件和责任。附件承载逐套价表、完整测算、长合同条款、逐分钟流程、明细图纸和补充口径。

不得把支撑核心结论的依据全部移到附件，也不得把主稿原样复制到附件。附件页同样需要标题、单位、日期和可读版面。

## 页序终审

1. 只读标题，能否复述议题由来、结果、原因、建议和所需行动？
2. 每个关键结论能否找到对应事实、比较、图纸或计算？
3. 同一主张是否被换词重复，缺少新增证据？
4. 删除某页是否损失独立信息？无损失则合并或删除。
5. 是否把一项完整论证拆成多页提词卡？需要时重新编组。
6. 主席能否找到结果和决策项，管理层能否找到责任和日期，外部对象能否找到履约与诉求？
7. 结尾是否产生本次会议真正需要的结果？
